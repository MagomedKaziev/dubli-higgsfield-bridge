# Дубли × Higgsfield bridge

Маленький MCP-сервер: получает промпт для одного кадра, дёргает Higgsfield
REST API, ждёт результат, сам скачивает картинку (у него своя сеть, без
ограничений) и отдаёт её байтами прямо в приложение — без внешних ссылок,
которые CSP артефакта не пропустит.

## 1. API-ключ

Получить в https://console.higgsfield.ai — формат `key_id:key_secret`.
Никуда, кроме переменной окружения `HIGGSFIELD_API_KEY` на хостинге, его
вставлять не нужно — в репозиторий он не попадает (см. `.gitignore`).

## 2. Деплой на Render.com

1. Залей эту папку в свой GitHub-репозиторий.
2. На render.com: **New → Web Service** → подключи репозиторий.
3. Environment: **Docker** (в репозитории уже есть `Dockerfile`).
4. Environment Variables:
   - `HIGGSFIELD_API_KEY` = `<твой key_id:key_secret>`
   - (по желанию) `BRIDGE_SHARED_SECRET` — см. `.env.example`
5. Deploy. После сборки Render даст публичный адрес вида
   `https://dubli-bridge.onrender.com`.
6. MCP-эндпоинт — `https://dubli-bridge.onrender.com/mcp`.
   Проверить, что сервис жив: `https://dubli-bridge.onrender.com/health` → `ok`.

## 3. Подключить как коннектор в claude.ai

Settings → Connectors → Add custom connector → вставить адрес `.../mcp`,
дать имя (например «Дубли-бридж»). После подключения — включить его для
этого чата, если попросит.

## 4. Дальше

Напиши мне (Claude) точное имя коннектора, которое ты дал на шаге 3 — я
пропишу его в прототип (`capabilities.mcp.servers`) и добавлю кнопку

16 раз (по одному на каждую ячейку матрицы 4×4) и сама разложит результаты
по карусели через `assets.upload()`.

## Важно про модель

Инструмент дергает `/higgsfield-ai/popcorn/auto` — это единственная
публично задокументированная text-to-image модель Higgsfield REST API,
подходящая под задачу (один промпт → картинка, свой aspect_ratio).
Модель `gpt_image_2_5 / sunburst`, которой генерировался тестовый грид в
чате, в публичном REST API не задокументирована — похоже, она доступна
только через MCP-коннектор Higgsfield в чате, не через ключ API.
Если результат по качеству не устроит — можно попробовать
`/higgsfield-ai/soul/standard` (правка в `server.js`, функция
`createGeneration`).

Документация Higgsfield на разные модели/статусы отвечает
непоследовательно (три разных пути для статуса в разных источниках), так
что `server.js` разбирает ответ защитно — ищет поле состояния и ссылку на
картинку по паттерну, а не по жёстко зашитому имени поля. Если после
деплоя генерация не находит картинку — глянь логи Render (`console.error`
там печатает сырой ответ) и пришли мне, поправлю под реальную форму
ответа.
